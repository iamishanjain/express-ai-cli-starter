## [0.2.0]

First public release as **ExpressForge** (previously `express-ai-cli`).

### Added

- First-run interactive setup: asks whether to enable AI, masked API-key prompt, live key verification with retry.
- Secure credential storage through the OS credential store (`@napi-rs/keyring`), with an explicit, consent-based `0600` file fallback.
- `config` commands (`show`, `get`, `set`, `validate`, `remove`) and `providers list`.
- Deterministic configuration precedence: flags, environment, stored config, defaults. Versioned config file with a migration framework.
- Provider abstraction (`AIProvider`, registry, factory, metadata) with Gemini as the only implemented provider.
- Template engine driven by `template.json` manifests under `templates/`.
- Non-interactive mode, `--yes`, `--ai/--no-ai`, `--approve-schema`, `--install/--no-install`, meaningful exit codes, graceful Ctrl+C handling.
- Typed errors with codes and recovery hints; redaction of secrets in all output.
- Test suite (Vitest), ESLint with architectural layering rules, Prettier, CI and publishing workflows.

### Changed

- The CLI is now published as `expressforge`; `create-express-ai` remains as a second bin name.
- Generated `package.json` dependencies are sorted alphabetically.
- Generated README says "Generated by ExpressForge".
- Projects are generated from templates instead of hardcoded strings; output is otherwise identical.
- AI responses get stricter validation: size limits and control characters stripped. The `ProjectSpec` shape and `schemaVersion: 1` are unchanged.
- `npm install` now runs without blocking the spinner, without a shell, and failures show a redacted output tail.

### Removed

- The `dotenv` dependency in the CLI. ExpressForge no longer loads a `.env` file from the current directory (this could pick up an unrelated project's key). Use `expressforge config set` or the `GEMINI_API_KEY` environment variable. `GEMINI_MODEL` still works.

### Security

- API keys are stored in the OS credential store instead of requiring a plaintext `.env` file, and are never written to generated projects.
- Path-traversal protection for template output; existing files are never overwritten.
- Upgraded `zod` to v4, which fixes a memory-exhaustion advisory (GHSA-mrhx-c7xc-m3w5) when validating oversized collections such as AI output.
